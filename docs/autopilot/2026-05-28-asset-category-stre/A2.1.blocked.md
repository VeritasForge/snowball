# Blocked: A2.1 · 2026-05-29

## 차단 사유

**분류**: 외부 의존 (USER-ACTION required)

A2.1의 "Prod data audit"은 prod/staging/dev DB에 5개 SQL 쿼리를 실행해 `asset.category` 컬럼 상태와 `(account_id, code)` duplicate 여부를 확인하는 단계다. Autopilot은 다음 사항으로 인해 직접 실행이 불가능하다:

1. `backend/src/snowball/infrastructure/db.py`의 `DATABASE_URL`이 hardcoded Postgres URL이며 실제 가용 여부 알 수 없음
2. `.db` 파일도 없음 (SQLite fallback 없음)
3. prod/staging DB 접속 자격 증명은 환경 자체에 존재 (autopilot 컨텍스트 외부)

## 시도한 방법

- `cat backend/src/snowball/infrastructure/db.py` — Postgres URL hardcoded 확인
- `ls backend/*.db` — `.db` 파일 부재 확인

## 필요한 결정 / 외부 의존

사용자가 직접 다음을 실행:

```bash
# 각 환경 (dev, staging, prod)에서 실행
psql "$DATABASE_URL" <<'EOF'

-- 1. DISTINCT category + count
SELECT DISTINCT category, COUNT(*) FROM asset GROUP BY category;

-- 2. NULL
SELECT COUNT(*) FROM asset WHERE category IS NULL;

-- 3. trailing whitespace
SELECT COUNT(*) FROM asset WHERE category != TRIM(category);

-- 4. empty string
SELECT COUNT(*) FROM asset WHERE category = '';

-- 5. duplicate (account_id, code)
SELECT account_id, code, COUNT(*) AS dup_count
FROM asset
WHERE code IS NOT NULL
GROUP BY account_id, code
HAVING COUNT(*) > 1;

EOF
```

- `docs/superpowers/plans/audit-results-2026-05-29.md`
- 템플릿은 plan 파일 §A2.1 Step 2 참고

이후 결과에 따라 결정 트리 적용:

| 케이스 | 다음 단계 |
|--------|---------|
| 모든 결과 clean | A2.2 skip → 바로 A3.1 진입 |
| 알 수 없는 값 ≤5개 | enum 멤버 추가 → A2.2 skip → A3.1 |
| 알 수 없는 값 >5개 또는 NULL/whitespace 존재 | A2.2 backfill migration 작성 |
| (account_id, code) duplicate 존재 | 수동 정리 또는 backfill 후 A3.10에서 partial unique index 적용 |
