# 스노우볼: 자동 매매 vs 추천 전략 분석

작성일: 2026-02-16

## 배경

스노우볼 서비스에서 고객이 사용하는 증권사 API를 연동하여 자동 매매를 구현할 경우, 해킹 시 보상 책임과 법적 리스크가 발생할 수 있습니다. 이에 대한 대안으로 **자동 매매 없이 추천만 제공**하는 전략을 검토했습니다.

---

## 전략 비교

| 구분 | 자동 매매 | 추천만 제공 (선택 전략) |
|------|-----------|------------------------|
| 금융 규제 | 투자일임업 등록 필요 (금융위) | 정보 제공 서비스 (등록 불필요*) |
| 해킹 시 책임 | 직접적 재산 손실 → 배상 책임 높음 | 데이터 유출 → 상대적으로 제한적 |
| 증권사 API 약관 | 자동 매매 제한 가능성 | 조회 API만 사용 → 충돌 낮음 |
| 투자 손실 발생 시 | "시스템 오류로 손해" 주장 가능 | "내가 직접 결정" → 책임 명확 |
| 개발/운영 복잡도 | 높음 (주문 실패 재시도, 체결 추적 등) | 낮음 (조회 + 계산만) |
| 사용자 신뢰 | 불안감 ("프로그램에 계좌 맡김") | 통제감 ("내가 직접 결정") |

\* 단, "투자권유"로 해석되지 않도록 주의 필요

## 핵심 장점

### 1. 법적 위험 최소화

**투자권유 금지**가 핵심입니다:

```
❌ 위법 (투자권유로 해석될 수 있음)
"지금 삼성전자를 사세요!"
"내일 오를 것입니다!"
"이 종목은 수익률이 높습니다!"

✅ 합법 (정보 제공)
"현재 주식 비중이 목표보다 5% 낮습니다"
"리밸런싱을 위해 다음 종목을 고려해보세요"
"과거 3년 평균 수익률은 8%입니다 (미래 수익 보장 안 됨)"
```

### 2. 개발 복잡도 대폭 감소

자동 매매 시 필요:
- ✗ 증권사 API 주문 권한 (보안 등급 높음)
- ✗ 주문 실패 시 재시도 로직
- ✗ 체결/미체결 상태 추적
- ✗ 주문 취소/정정 기능
- ✗ 증권사 시스템 장애 대응
- ✗ 실시간 잔고/체결 동기화
- ✗ 24시간 모니터링 필요

추천만 제공 시 필요:
- ✓ 조회 API로 현재 보유 종목 확인
- ✓ 리밸런싱 계산
- ✓ 추천 결과 표시
- ✓ (선택) 푸시 알림

### 3. 사용자 신뢰 확보 용이

사용자 심리:
- ❌ "내 계좌를 프로그램에 맡긴다" → 불안감
- ✅ "프로그램이 조언하면 내가 결정한다" → 통제감

## 국내 성공 사례

### 1. 불릿 (Bullit)
- 서비스: ETF 포트폴리오 추천
- 매매: 사용자가 직접
- 수익: 프리미엄 구독 (월 9,900원)

### 2. 핀다 (Finda)
- 서비스: 금융 상품 비교/추천
- 가입: 사용자가 직접
- 수익: 제휴 수수료

### 3. 토스증권 (현 카카오페이 증권)
- 서비스: 자산 분석 및 추천
- 매매: 사용자가 직접 (원클릭으로 MTS 연결)

## 법적 주의사항

### 1. 명확한 책임 한계 표시

```markdown
⚠️ 투자 유의사항
- 본 서비스는 투자 조언이 아닌 참고 정보를 제공합니다
- 최종 투자 결정은 이용자 본인의 책임입니다
- 투자 결과에 대해 스노우볼은 책임지지 않습니다
- 투자 손실 발생 가능성이 있습니다
```

### 2. 개인정보 최소 수집

```python
# ✅ 수집해도 되는 정보
{
    "portfolio": {
        "ticker": "005930",
        "quantity": 10,
        "avg_price": 70000
    }
}

# ❌ 수집하면 안 되는 정보
{
    "user": {
        "ssn": "900101-1234567",  # 주민등록번호
        "account_number": "123-45-67890",  # 계좌번호
        "password": "...",  # 증권사 비밀번호
    }
}
```

## UX 개선 방안 (자동 매매 없이도 편리하게)

### 방법 1: 딥링크 (Deep Link)

```
스노우볼 화면:
┌────────────────────────────────┐
│ 📊 오늘의 리밸런싱              │
│                                 │
│ 삼성전자(005930) 5주 매수 필요  │
│ 예상 금액: 350,000원            │
│                                 │
│  [📱 MTS에서 주문하기]  ← 클릭 │
└────────────────────────────────┘
         ↓ 딥링크 실행
┌────────────────────────────────┐
│ 📱 증권사 MTS 자동 실행         │
│ (주문 화면으로 바로 이동)       │
│                                 │
│ 종목: 삼성전자 (005930) ✅ 자동 │
│ 수량: 5주 ✅ 자동               │
│ 가격: 시장가                    │
│                                 │
│        [주문하기]               │
└────────────────────────────────┘
```

**구현**:
```typescript
const openMTS = (order: Order) => {
  const deepLink = `kiwoom://order?code=${order.ticker}&qty=${order.quantity}&type=buy`;
  window.location.href = deepLink;
};
```

소규모 자산운용사, 투자자문사에 화이트라벨 제공

## 최종 결론

> **"자동 매매 없이 추천만 제공"은 1인 개발자에게 최적의 전략입니다.**

**이유**:
1. ✅ 법적 위험 최소화 (투자일임업 등록 불필요)
2. ✅ 해킹 시 책임 제한적
3. ✅ 개발/운영 복잡도 대폭 감소
4. ✅ 사용자 신뢰 확보 용이
5. ✅ 증권사 API 의존도 낮음
6. ✅ 수익화 모델 다양 (구독, 제휴 수수료)

**주의사항**:
- "투자권유"로 해석되지 않도록 용어 선택 신중
- 명확한 책임 한계 표시
- UX 개선으로 편의성 보완 필수

**다음 단계**:
1. 서비스 약관 작성 (변호사 검토 권장, 1회 30-50만원)
2. 금융보안원 무료 컨설팅으로 법적 문제 사전 확인
3. MVP 출시 후 사용자 반응 확인
